# Загрузка сайта на GitHub Pages

Эта папка — готовая финальная версия сайта курса «Моушн-дизайн».

## 1. Что загружать

В репозиторий нужно загружать **содержимое этой папки**, а не ZIP-файл и не внешнюю папку целиком.
В корне репозитория должны оказаться, среди прочего:

```text
index.html
styles.css
script.js
topics.js
lecture.js
resources.js
.nojekyll
assets/
lectures/
resources/
studio/
```

Особенно важно, чтобы `index.html` лежал прямо в корне репозитория.

## 2. Первая публикация

1. Создайте репозиторий на GitHub.
2. Откройте `Add file → Upload files`.
3. Перетащите все файлы и папки из этой папки сайта.
4. Нажмите `Commit changes`.
5. Откройте `Settings → Pages`.
6. В `Build and deployment` выберите `Deploy from a branch`.
7. Выберите ветку `main` и папку `/ (root)`.
8. Нажмите `Save`.

Через некоторое время сайт будет доступен по адресу GitHub Pages.

## 3. Обновление уже работающего сайта

Если GitHub Pages уже настроен, повторно открывать `Settings → Pages` не нужно.
Просто замените изменённые файлы и сделайте `Commit changes`.

После обновления, если браузер показывает старую версию, выполните жёсткое обновление:

- Windows/Linux: `Ctrl + F5`
- macOS: `Cmd + Shift + R`

## 4. Что нельзя ломать

- Не перемещайте `index.html` из корня.
- Не меняйте структуру `assets/`, `lectures/`, `resources/` и `studio/`, если не понимаете, какие пути придётся исправлять.
- Для новой лекции `slug` в `topics.js`, имя HTML-файла и `data-topic` должны совпадать. Через Studio это делается автоматически.
- Не удаляйте `.nojekyll`.

## 5. Резервная копия

Перед крупными изменениями удобно скачать ZIP репозитория (`Code → Download ZIP`) или оставить предыдущий commit в GitHub. История GitHub позволяет вернуть старую версию файла.
