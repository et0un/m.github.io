# Studio: вход, работа и авторизация на разных устройствах

Редактор курса открывается только по прямому адресу:

```text
https://ВАШ-АДРЕС-GITHUB-PAGES/studio/
```

Ссылки на Studio на публичных страницах сайта нет.

## Вход в Studio

Используйте логин и пароль, которые были заданы при создании редактора. Они одинаковые на компьютере, ноутбуке, планшете и телефоне.

Авторизация Studio хранится в `sessionStorage`, поэтому на новом устройстве, в другом браузере или после закрытия вкладки может потребоваться войти заново.

> Важно: GitHub Pages — статический хостинг. Такой вход скрывает редактор от обычного посетителя, но не является полноценной серверной защитой. Не храните в Studio секретные данные.

## Подключение прямой публикации в GitHub

Откройте в Studio блок **«Публикация GitHub»**.

Нужно указать:

- **Владелец** — GitHub username владельца репозитория;
- **Репозиторий** — имя репозитория;
- **Ветка** — обычно `main`;
- **Fine-grained token** — токен GitHub с правом записи.

Для токена нужен доступ к нужному репозиторию и разрешение:

```text
Repository permissions → Contents → Read and write
```

После ввода нажмите **«Проверить»**.

### Что сохраняется между устройствами

- логин/пароль Studio — одинаковые везде;
- owner/repo/branch сохраняются локально в конкретном браузере и могут определиться автоматически;
- GitHub token хранится только в текущей сессии браузера и **не записывается в файлы сайта**;
- на другом устройстве или в новой сессии token нужно ввести снова.

Для трёх репозиториев можно создать один fine-grained token с доступом к этим трём репозиториям либо отдельный token для каждого.

Никому не отправляйте token. Если устройство потеряно или token случайно раскрыт, отзовите его в настройках GitHub и создайте новый.

## Работа с лекциями

Вкладка **«Лекции»** позволяет:

- выбрать существующую тему;
- создать новую;
- менять название и теги;
- писать и форматировать текст;
- добавлять изображения с компьютера или по URL;
- перетаскивать изображения в текст;
- вставлять YouTube и Vimeo;
- публиковать лекцию непосредственно в GitHub;
- скачать HTML/ZIP как резервный способ.

### Вставка видео

Нажмите **«Видео YouTube / Vimeo»** и вставьте обычную ссылку, например:

```text
https://www.youtube.com/watch?v=...
https://youtu.be/...
https://vimeo.com/123456789
```

Можно также вставить готовый iframe-код YouTube/Vimeo. Редактор сам преобразует ссылку в корректный embed.

### Удаление видео или картинки

1. Нажмите на видео или изображение в живом предпросмотре.
2. Выбранный медиаблок получит цветную рамку.
3. Нажмите **«Удалить медиа»** в панели форматирования.

Видео в Studio специально не перехватывает клики, чтобы его можно было выбрать и удалить. На опубликованной странице iframe работает как обычно.

## Главная страница

Во вкладке **«Главная страница»** можно менять:

- заголовок и текст «О курсе»;
- заголовок блока полезных ссылок;
- иконки, названия и адреса карточек.

После правок нажмите **«Опубликовать на GitHub»**. Если прямое подключение не настроено, используйте **«Скачать index.html»** и замените файл вручную.

## Страницы ссылок

Во вкладке **«Страницы ссылок»** редактируются страницы материалов, ПО, зачёта/экзамена, контактов, требований и этапов работы. Текст и карточки редактируются прямо в предпросмотре.

## Черновики

Редактор автоматически сохраняет черновики локально в браузере. Это не равно публикации. Публичный сайт меняется только после нажатия **«Опубликовать на GitHub»** или ручной загрузки скачанных файлов.

## Если что-то не обновилось

1. Дождитесь обновления GitHub Pages.
2. Сделайте `Ctrl + F5` / `Cmd + Shift + R`.
3. Проверьте, что Studio открыта именно с опубликованного HTTPS-сайта, а не локально из папки.
4. При ошибке GitHub-публикации проверьте owner, repo, branch и разрешение `Contents: Read and write` у токена.
